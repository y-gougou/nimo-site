## 一、容器生命周期

昨天学会了 `docker run`（创建 + 进入 + 退出）。今天学**不重新创建**，直接操控已有容器 —— 核心是生命周期状态机：

    create → start → running → stop → exited → rm
              ↑                          ↓
              └────── start（再启动）──────┘

实验观察：

- `docker start zealous_merkle`：容器 ID 不变，STATUS 从 Exited → Up —— **start 是唤醒，不是新建**
- `docker exec -it <容器> bash`：钻进**运行中**的容器，exit 退出后容器**继续跑**（PID 1 还活着）—— 与 `run -it` 里 exit 杀掉 PID 1 完全不同
- 容器里敲 `docker` 报 command not found：CLI 是宿主机的工具，容器里没有 —— 隔离的铁证
- `docker stop`：docker ps 里消失、ps -a 里变 Exited —— 停车 ≠ 删除
- `docker rm`：从 ps -a 彻底消失 —— 报废，不可恢复；但 `docker images` 里镜像还在（模具还在）

意外收获 —— 退出码：hello-world 是 `Exited (0)`（正常结束），而 stop 的 bash 容器是 `Exited (137)`（128+9，被 SIGKILL 强杀）。`docker stop` 会先发温柔信号等 10 秒，不响应才强杀。

## 二、容器数据问题（科研重点）

**实验 A：体验数据消失**

    docker run -it ubuntu bash          # 建容器
    echo "重要数据" > /important.txt    # 写数据
    exit                                # 退出
    docker rm <容器>                    # 删容器
    docker run --rm ubuntu cat /important.txt
    # → cat: /important.txt: No such file or directory

结论：容器是临时的，rm 一删，里面写的东西全跟着消失。镜像只会重建"干净的初始环境"。

**实验 B：Bind Mount 救回数据**

    mkdir ~/docker-data
    docker run -it -v ~/docker-data:/data ubuntu bash
    echo "persistent" > /data/hello.txt
    exit && docker rm <容器>
    ls ~/docker-data        # hello.txt 还在！

关键理解：

- `-v 宿主机目录:容器目录` = 挂载 —— **同一个地方的两个视角**，不是复制
- 写入双向可见：容器里写宿主机看到，宿主机写容器里看到
- 容器删了，宿主机目录毫发无损
- 类比：给容器插 U 盘 —— 播放器（容器）删了，U 盘（数据）还在

## 四、端口映射（对外开门）

    docker run -d -p 8080:80 --name web-demo nginx

新参数：`-d` = 后台运行（服务器类容器的标准姿势）；`--name` = 起名字；`-p 外面:里面` = 端口映射。

**为什么需要两个端口**：容器有独立的网络世界 —— 房间里的 nginx 监听"房间内"的 80，但外面的人够不到。`-p 8080:80` = 在墙上开一扇窗：外面（宿主机）8080 → 里面（容器）80，Docker 负责转接。

验证：`curl http://127.0.0.1:8080` 返回 nginx 欢迎页 HTML（浏览器打开就是 "Welcome to nginx!"）。`docker ps` 的 PORTS 列 `0.0.0.0:8080->80/tcp` 就是这扇窗的施工图。

**应用**：所有"要给别人访问"的服务都是这个模式 —— Jupyter（8888）、数据库（5432）、ROSBridge（9090）、自己写的 API。端口默认值只是习惯，不是法律，可以改（容器内 5432 映射到外面 15432 都行，只要外面不被占）。

## 五、容器网络（对内组网）

    docker network create ypnet                        # 拉一根内部专线
    docker run -d --name web1 --network ypnet nginx    # 容器接入专线
    docker run --rm --network ypnet busybox wget -O- http://web1   # 用名字访问！

三种网络模式：`bridge`（默认，容器连在虚拟桥上）、`host`（直接用宿主机网络）、`none`（无网络）。

**核心知识**：同一自定义网络里的容器，**用名字互访**（Docker 内置 DNS 把容器名翻译成 IP，不用记地址）。

**端口映射 vs 容器网络（防混关键）**：

    -p 8080:80     = 对外开门（外面的人 → 容器），给外部访问用
    --network xxx  = 容器之间拉专线（容器 ↔ 容器），给内部通信用

**未来架构**：前端容器 →（名字）→ 后端容器 →（名字）→ 数据库容器。对外只开前端一扇门，数据库不映射端口（只对内部，不给外面看，安全）。

## 六、补课：前后端与网络基础

> 这节是为了补 Docker 网络的地基 —— 前端/后端、IP/端口这些概念，来自真实 Web 世界的通用知识。

**前后端是什么**：前端 = 用户看到、操作的部分（浏览器页面）；后端 = 干活的程序（处理请求、操作数据）。两者是两个独立程序，靠"请求-响应"通信（类比：菜单/服务员 = 前端，厨房 = 后端）。nimo-site 是纯前端（GitHub Pages 只存 HTML）；dsh 是前端+后端（浏览器 → dsh 进程 → LLM API）。

**网络寻址两层**：IP = 哪台电脑（楼），端口 = 哪个程序（房），`IP:端口` 定位一个服务 —— 学校 API 的 baseURL `xplt.sdu.edu.cn:4000` 就是这个格式。

**完整请求链路**：浏览器 → 解析域名成 IP → 连接 IP:端口 → 发请求 → 后端处理 → 响应回来 → 浏览器展示。

**容器加入后**：-p 管"外面→容器"，--network 管"容器↔容器"。回看 dsh：浏览器 → `127.0.0.1:3080`（端口寻址）→ dsh 后端 → 学校 API（前端访问后端的完整实例）。
